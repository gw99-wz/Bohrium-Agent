# 限制与已知问题（LIMITS）

这份文件存在的意义是：评审在跑之前就知道哪里会出问题，而不是被"全自动"的说法误导。

## 1. 抽取

| 限制 | 具体表现 | 影响 | 现在的处置 |
| --- | --- | --- | --- |
| 扫描件/纯图片 PDF | 无文字层，抽不到任何字符 | 无法翻译 | `preflight` 标 `scanned_pages`；需外部 OCR 或用视觉模型逐页转写（SKILL.md 有流程），结果记 `partial` |
| 无 PyMuPDF 且无 `pdftotext` | 只能拿到"无文本"错误 | 无法抽取 | 报 `no_pdf_extractor` 并给出安装提示；或由 Agent 自备文本 |
| 跨栏大图/大表 | 阅读顺序可能错位 | 段落归位错 | 手工把该块标为 `image` 后重跑 `segment.py` |
| 三栏及以上版式 | 只按"两栏"建模 | 顺序错 | 未支持；建议按页导出后人工校核 |
| 表格结构 | 只做"表格像"的启发式标记 | 单元格行列关系丢失 | 不声称还原表格；表头与数值原样保留，行列关系需人工核对 |
| 公式 | 只保护符号，不做 LaTeX 化 | 复杂公式仍是原文字符 | 题注与编号保留；公式本体如需排版需人工转写 |
| 参考文献 | 只切出参考文献区 | 不逐条结构化（作者/年份/DOI） | 整块保留，编号原样；结构化需额外模块 |
| PDF 文本层带连字符换行 | `identifica-tion` 类 | 已按行合并规则修复 | 仍有少量专有名词可能被误合并 |
| 深色背景/水印文字 | 可能混入正文 | 噪声段 | 需人工在 `segments.jsonl` 删除并保持编号连续 |

## 2. 术语

- **种子表只覆盖有限学科**（默认二维材料/光谱学，约 70 条）。换学科必须替换 `resources/glossary_seed.tsv`，否则 `suggest` 只给候选、全靠人填 `zh`。
- **自动抽取只是候选**：多词短语靠 n-gram 频次，会混入 "in this Letter" 这类非术语，需人工删。
- **不校验"译名对不对"，只校验"全篇用没用同一个"**：把 `band gap` 统一译成"苹果"也能通过一致性检查。译名质量靠人工或模型判断，这不在检查范围内。
- **词形变化只支持简单复数**（`-s/-es`）。`exfoliated`/`exfoliation` 视为不同词。
- **中英混排**：中文段会被当作"不该译"的部分保留，但如果原文整段是中英混杂，需要人工指定。

## 3. 校验

- 数字比对是**多重集**级别，不理解语义：`0.6 eV` 里的 0.6 保住了，但"减少了 0.6 eV"被译成"减少了 0.6 mV"仍会通过（单位单独检查，也可能同时通过）。语义级核对不在范围内。
- 否定检测是线索词级别，中文"不"在"不同/不仅"里会误报或漏报；这一项只作为**待确认清单**，不作硬错。
- 图表编号互认 `Fig. 3a` ↔ `图 3a`；若译者改写为"第三幅图 a"，会报缺失。
- 长度比阈值（0.12–1.3）是经验值，对"公式为主"或"术语列表"段落会误报。
- **无法判断译文是否通顺、是否学术得体**——这需要人。

## 4. 评测

- 对照实验只有 **1 篇文献的 7 个段落（2183 字符）**，且 baseline 由同一模型完成。这是演示协议与工具链，不是统计结论；规模放大后的数字会变，尤其是术语漂移与漏段率。
- 指标由正则与计数得出，**不能代替人工评审**；它的价值是可复算、可争论（口径写在 `eval/metrics.py` 顶部）。
- 没有做多篇、多学科、多模型的交叉验证。

## 5. 工程

- 只在 Windows + Python 3.15 上实测；脚本按 POSIX 安全写法（无硬编码路径、`Path` 处理），但**未在 Linux 实机跑过**（本机无 WSL/Docker）。`/input`、`/app/work`、`/app/output` 是默认值但未在评测容器内验证。
- 大文件（>100 页）未做流式处理，`blocks.jsonl` 会一次性载入内存；粗估 100 页约 20–40 MB，属于可接受范围但未压测。
- 并发未做：多个包同时写 `work/translation/` 是安全的（不同文件），但同时跑两个 `check.py` 会互相覆盖 `translations.jsonl`。
