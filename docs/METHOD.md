# 方法说明（METHOD）

## 1. 问题不是"译得好不好"，而是"错在哪能被发现"

一句翻译通不通顺，机器判断不了；但下面四件事机器判断得了，而且正是文献翻译最容易出错的地方：

1. 同一术语是否只有一种译名；
2. 段号是否连续、每段是否都有译文；
3. 原文的数字、单位、`[n]`、图表编号是否还在；
4. 每段译文能否指回原文的页码与段落。

本 Skill 把这四件事变成**文件 + 退出码**，翻译由 Agent 做，判定由程序做。

## 2. 七个机制

### 2.1 段落重建（extract.py）

很多 PDF 的文本块是"一行一块"。直接把块当段落，摘要会被切成十段，句子会跨段腰斩。所以先按视觉行收集，再用三个独立信号断段：

| 信号 | 判据 | 拦住的错误 |
| --- | --- | --- |
| 行距比 | `gap / median_gap > 1.35` | 段间留白 |
| 短末行 | 上一行宽度 < 0.9 × 栏宽 且 以上句末标点结尾 | 两端对齐段落的最后一行 |
| 标题标签 | Abstract / Introduction / 数字编号标题 / 全大写短行 | 标题粘进正文 |

反例保护：`PACS numbers:`、`*Corresponding author`、`DOI:` 这类前置件强制断开，避免与正文首段粘连；单组超长时在句末标点处强制切分（上限 1800 字符），防止整页变成一段。

**与"直接扔给模型"的差别**：模型看到的是已经边界正确的段落，不需要它自己判断哪里开始哪里结束——这恰好是它最不擅长、也最不可复现的部分。

### 2.2 双栏阅读顺序

把页面按"宽块"切成水平带（标题、通栏图、大表），带内按栏号再按 y 排序。判两栏的条件是左右两组文本**在水平方向不重叠**，而不是简单的"数量够多"——后者会把单栏短行误判成两栏。

### 2.3 跨页/跨栏续接（segment.py）

段落在页底或栏底被切断时，下一页/下一栏开头是它的后半句。判据：上一段不以句末标点结尾，且长度足够（>150 字符），且确实跨了页或栏。合并后必须把"当前所在页/栏"更新为新块的页/栏，否则会连续吞并后续所有段落（这是一个真实踩过的坑，回归测试里有对应用例）。

### 2.4 页级字符对账

每页抽到的字符数 vs 被段落覆盖的字符数，差值全部归因：页眉页码（furniture）、图片、或"没归因"的差额。`char_ratio < 0.98` 或有扫描页 → `coverage_pass=false`，直接提示"这页可能漏了"。

**这是"段落全"唯一可量化的证据**：不是声称没漏，而是逐页对账。

### 2.5 术语冻结（glossary.py）

```
suggest → glossary.tsv（含首现段号/上下文/出现次数）
  ↓ 人工或 Agent 填 zh
lock    → glossary.lock.tsv + sha256 写入 glossary.lock.json
check   → 逐段比对：出现 src 的段落，译文里必须有 zh（或 zh_alt）
```

三点设计取舍：
- **冻结而不是"每次重新生成"**：翻译过程中不允许悄悄改变译名；改了就要重新 `lock`，哈希会变，可审计。
- **按段回填校验，而不是全局打分**：能精确指出"第 S0007 段把 band gap 译成了别的"，而不是给一个模糊的一致率。
- **允许 `zh_alt`、`keep`、`skip`**：真实术语有同义写法（`带隙|能隙`），材料式（`MoS2`）应保留原文，管不了的术语显式跳过——比强行 100% 更诚实。

### 2.6 守恒校验（check.py）

| 检查 | 方法 | 级别 |
| --- | --- | --- |
| 数字 | 去掉 `[n]` 后取数字多重集，比缺失与新增 | 缺=error，多=warn |
| 单位 | 单位词表多重集 | warn |
| 引用 | `[12]`、`[1-19]`、`[2, 5, 6, 11]` 归一化后比对 | error |
| 图表/公式编号 | `Fig. 3a`/`图 3a`、`Table 1`、`Eq. (2)` 互认，编号必须一致 | warn |
| 公式 | 数学符号/上下标标记是否还在 | warn |
| 否定/限定 | 英文强否定线索 vs 中文否定线索 | warn |
| 长度 | 译/原字符比超出 [0.12, 1.3] | warn |
| 完整性 | 段号缺失/重复/空译/非中文 | error |

error 项让 `check.py` 退出码非 0，`run.py finish` 因此不可能"带病交付"。

### 2.7 契约回填（render.py）

`case.json` 的 `output_contract` 字段名事先未知，所以按语义关键词映射（translation/bilingual/glossary/evidence/status/uncertainty/…）。映射不上的字段写 `null` 并进 `contract_notes` 与 `uncertainty`——**宁可交白卷也不编造**。这条在回归测试里有断言。

## 3. 对照实验

### 3.1 协议

同一篇文献、同一段原文（PRL 105, 136805 的前 7 个段落：标题、作者单位、Abstract 标题、摘要、PACS、通讯作者、正文首段，共 2183 字符），同一任务要求（`task.md`：全文译为中文、术语统一、保留数字与引用）。

| 组 | 条件 |
| --- | --- |
| baseline | 只给原文与任务要求，不给术语表、不给段号、不给上下文；一次性输出连续中文 |
| skill | 走完整流水线：先 `glossary suggest` → 锁定 8 条术语 → `packet build` 带上下文与术语 → 逐段译 → `check` → `render` |

两组都由同一个模型完成，唯一变量是"有没有这套流程"。

### 3.2 结果（`eval/runs/prl2010_excerpt/scorecard.md`）

| 指标 | baseline | skill |
| --- | --- | --- |
| 术语一致率（术语只出现一种译法） | 1.000 | 1.000 |
| 术语变体总数（越少越好） | 7 | 7 |
| 数字保留率 | 1.000 | 1.000 |
| 引用标记保留率 | 1.000 | 1.000 |
| 图表引用本地化率 | 0.000 | 1.000 |
| 段号可回指率 | 0.000 | 1.000 |
| 是否标注不确定 | 否 | 是 |
| 可回指段数 | 0 | 7 |

### 3.3 怎么读这张表（包括对我不利的部分）

**打平的三项要直说**：在这 7 段、2183 字符的规模上，baseline 的术语、数字、引用全部正确。短文本、单一主题时，一个称职的模型本来就能保持一致——**术语一致性只有在长文、多章节、跨图注时才会漂移**，而这次实验没有覆盖那个规模。

**真正拉开差距的是三件事**：

1. **图表引用本地化 0→1**：baseline 把 `Fig. 1a` 原样留在中文里；skill 输出「图 1a」，且编号一致。
2. **可回指 0→7**：baseline 的 7 段没有任何段号，评审无法把某句译文精确指回原文页码/段落；skill 每段带 `S000x`、页码、章节、block id。
3. **不确定标注**：原文 "the relatively weak interactions **between these layers** and the strong **interlayer** interactions" 自相矛盾（疑为 interlayer/intralayer 笔误）。baseline 直接按物理常识改译成「层内」，读者看不出这里有问题；skill 按字面译出并标 `uncertain` + 依据，进入 `pending_review.md`。哪个更"准"见仁见智，但**含混处理 vs 显式标注**的差别是可判定的。

**结论要克制**：这套东西的价值不在"比裸模型译得更好看"，而在把"译得对不对"变成可复核的检查项，并在长文上把一致性从"靠模型自觉"变成"程序不允许"。

## 4. 复现

```bash
# 1) 术语一致性/数字/引用
python eval/metrics.py eval/runs/prl2010_excerpt

# 2) 端到端（用仓库自带示例文本，无需 PDF）
python tests/test_pipeline.py

# 3) 换一篇论文重跑整条流水线
python scripts/run.py all --input <case>/input --work <case>/work --output <case>/output
```

`eval/metrics.py` 不调用任何模型：给定 `source.md`、`baseline.md`、`skill.md`（可选 `skill_bilingual.md`），纯正则/计数得出上表，评审可自行重算。

## 5. 中间文件字段

自己接文本（`no_pdf_extractor`）或手工补页时需要写的两个文件：

`work/blocks.jsonl`（每行一个块，段落级）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `page` | int | 1 起页码 |
| `pid` | str | 块 id，`p3-l012`/自定义，段内唯一 |
| `text` | str | 块正文（段内已合并的行） |
| `size` | float | 正文字号，未知填 0（会退化为启发式） |
| `bold` | bool | 是否加粗 |
| `math` | bool | 是否含公式符号/数学字体 |
| `col` | int | 栏号，单栏填 0 |
| `bbox` | [x0,y0,x1,y1] | 位置；未知填 `[0,0,0,0]` |

`work/segments_manual.jsonl`（每行一个补充段落）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `page` | 是 | 该段所在页 |
| `text` | 是 | 段落正文 |
| `kind` | 否 | `paragraph`/`heading`/`caption`/`formula`/`table_like`，默认 `paragraph` |
| `section` | 否 | 所属章节名，默认沿用上一段 |

## 6. 与已有做法的边界

| 做法 | 术语 | 段落 | 守恒 | 回指 | 本 Skill 的差异 |
| --- | --- | --- | --- | --- | --- |
| 提示词里写"术语要一致" | 靠自觉 | 靠自觉 | 靠自觉 | 无 | 变成文件与退出码 |
| 机器翻译 API | 词典级一致 | 按句切分 | 常丢格式 | 无 | 保留段号与图表编号，可逐段修 |
| 通用 PDF 转 Markdown | 不涉及 | 版面常错 | 不检查 | 有页码 | 在本 Skill 里是第 2 步，不是终点 |
| 人工翻译 + 校对 | 最好 | 最好 | 人工 | 人工 | 成本差异；本 Skill 定位是把机械检查自动化，人只处理 `pending_review.md` |
